# Survey Instrument & System Usability Scale (SUS) Protocol

**Last updated:** 2026-11-17  
**Status:** Ready for Week 9 post-pilot administration (NO responses collected or fabricated yet).

---

## 1. Pre-Pilot Requirement & Feature Priority Questionnaire (Week 1–2)
Target respondents: Owner, Shift Supervisor, Peer Powerloom Owners (`n = 5–8`).

1. Unit size (number of looms) & loom type (`Shuttle` / `Rapier` / `Other`).
2. Current record-keeping method (`Paper notebook` / `Excel` / `WhatsApp` / `Mobile app` / `Other`).
3. Biggest weekly headache (rank 1–5): Wage math · Trader rate cuts/balances · Beam completion tracking · EB bill surprises · Fabric defect disputes.
4. Willingness to adopt a ₹0 self-hosted phone tool (`1–5` scale) and maximum acceptable daily data-entry time (`<2 min` / `2–5 min` / `5–10 min`).

---

## 2. Post-Pilot System Usability Scale (SUS — Brooke / Bangor et al., 2008)
Rated `1` (Strongly Disagree) to `5` (Strongly Agree) after participants complete standardized tasks (log 1 shift, view weekly payslip, check trader rate alert, inspect 1 defect photo):

1. I think that I would like to use LOOMOS frequently.
2. I found LOOMOS unnecessarily complex.
3. I thought LOOMOS was easy to use.
4. I think that I would need the support of a technical person to be able to use LOOMOS.
5. I found the various functions in LOOMOS were well integrated.
6. I thought there was too much inconsistency in LOOMOS.
7. I would imagine that most people would learn to use LOOMOS very quickly.
8. I found LOOMOS very cumbersome to use.
9. I felt very confident using LOOMOS.
10. I needed to learn a lot of things before I could get going with LOOMOS.

**Scoring:** Odd items `(score - 1)`, even items `(5 - score)`, sum × `2.5` = `0–100` SUS score; benchmarked against Bangor et al. (2008) (~68 average, ≥70 good, ≥85 excellent).
